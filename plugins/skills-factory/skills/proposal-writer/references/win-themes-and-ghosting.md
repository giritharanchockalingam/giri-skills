# Win Themes and Ghosting

## 1. What a win theme is
A win theme is a client benefit, tied to something they care about, that we can prove and the alternative cannot match. Three to four per proposal. Each one appears in the executive summary, is developed in one or more sections, and is proven in the why-us section.

| Element | Test | Example (illustrative only) |
|---|---|---|
| Hot button | Quoted or cited from client evidence (discovery, RFP, filing). If we cannot quote it, it is our hot button, not theirs | "We re-key every order over $50k by hand." — VP Ops |
| Discriminator | Something we do that the alternative does not, or does worse, and that the client would value | Migration factory with automated interface conversion and parallel-run harness |
| Proof | Cleared reference with an outcome number; certification; demonstrable asset | Reference R-07 (cleared-anonymized): 240 interfaces migrated in 11 months, zero P1 incidents in parallel run |
| Ghost | The weakness of the alternative, stated as a client risk without naming anyone | "Approaches that migrate interface by interface without a parallel-run harness carry cutover risk into peak season." |

## 2. Discriminator tests
Apply all four. A discriminator failing any one is a feature, not a theme.
| Test | Question |
|---|---|
| Relevance | Does it map to a hot button the client stated? |
| Uniqueness | Can the incumbent or likely competitors say the same sentence? If yes, it is table stakes |
| Provability | Do we have a cleared proof point with a number? |
| Consequence | Can we state what the client loses without it, in their terms? |

Common false discriminators: "experienced team", "proven methodology", "customer-centric", "partnership approach", "global delivery". Every bidder claims them.

## 3. Ghosting rules
Ghosting sets evaluation criteria that favor us by raising the client's attention to risks the alternative carries.
| Do | Do not |
|---|---|
| State the risk as a general truth about approaches | Name the competitor or their product |
| Tie it to the client's own stated consequence | Invent a consequence they did not state |
| Follow immediately with how we remove the risk | Leave the ghost hanging as fear |
| Use in exec summary, approach, and risk sections | Use in the pricing section (reads as excuse) |

Ghost patterns by situation:
| Situation | Ghost line pattern |
|---|---|
| Incumbent with long tenure | "Continuity has value; it also carries the cost of the current run-rate and the assumptions built into it. The approach should include a baseline the client can audit." |
| Larger competitor | "Programs staffed from a bench rather than from the proposed team see leadership change mid-flight. Named leads and continuity commitments reduce that." |
| Cheaper competitor | "Estimates built without an interface inventory and complexity scoring tend to grow after award. We price from a scored inventory and state the drivers." |
| Product vendor bidding services | "A platform vendor's services team optimizes for platform adoption. An independent team optimizes for the client's outcome across platforms." |

## 4. Proof standards
| Proof type | Minimum content | Clearance |
|---|---|---|
| Reference project | Scope shape, scale numbers, outcome numbers, duration, role we played | Named or anonymized per client agreement; stored in the internal reference register |
| Certification | Standard, scope, issuing body, expiry | Public |
| Asset / accelerator | What it does, measurable effect (time, defects, cost), where it was used | Internal; outcome number cleared |
| Team credential | Role-relevant certifications and years; no personal narrative | Individual's consent for named use |

No proof → no theme. Drop it or downgrade it to a supporting claim without a proof line.
