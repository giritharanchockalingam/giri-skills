# Redline Method

## 1. Preserve the storyline
The author chose a narrative for reasons the reviewer may not see (politics, prior commitments, what the sponsor already said). The redline sharpens that narrative. It does not substitute the reviewer's preferred one.

| Allowed | Not allowed |
|---|---|
| Reorder two adjacent slides to fix a logic gap | Restructure the deck around a new framework |
| Add a missing executive-summary or decision slide | Add a new recommendation the author did not make |
| Merge two slides making the same point | Replace the author's options with different options |
| Move detail to appendix | Delete the author's evidence because "it is weak" (mark `[TBD]` for sourcing instead) |
| Rewrite titles and body for clarity | Change the ask (budget, decision) |

If the reviewer believes the storyline is wrong, that is a separate note to the author ("storyline risk"), not a redline action.

## 2. Title assertions
A title states the slide's conclusion. The body proves it. A reader who reads only titles gets the whole argument.

| Label title (replace) | Assertion title (use) |
|---|---|
| "Current state" | "Three platforms carry 80% of integration incidents" (or `[TBD]` for the figure) |
| "Options" | "Option B reaches first value in 6 months at the lowest delivery risk" |
| "Risks" | "Two risks need sponsor decisions this month" |
| "Timeline" | "Go-live before peak freeze requires a decision by <date>" |
| "Next steps" | "Three decisions today unlock wave 0 on <date>" |

Rules: ≤ 12 words; one claim; a number or a consequence; no question marks; no "overview of".

## 3. Slide patterns
| Pattern | Use when | Layout |
|---|---|---|
| Executive summary | Always, slide 1–2 | Decision asked · three reasons (number each) · next steps (owner, date) |
| Situation-complication | Opening | Left: facts with sources; right: what changed and why it matters now |
| Options comparison | Decision slides | Table: options × criteria, scored; recommendation highlighted |
| Evidence | Proving a claim | One chart or one table; title = the finding; source line |
| Plan | Timeline | Milestones with dates and dependencies; freeze windows shaded |
| Risk | Governance | Table: risk, likelihood, impact, mitigation, owner; top 5 only |
| Ask | Closing | Decisions needed, by whom, by when; what happens if delayed |

One point per slide. If a slide needs two titles, it is two slides or a table.

## 4. Density and time fit
| Rule | Value |
|---|---|
| Body slides for a decision deck | ≈ minutes ÷ 2 (30-minute slot → ≤ 15 body slides, typically 8–12) |
| Body slides for a discussion deck | ≈ minutes ÷ 4 |
| Words per slide body | ≤ 60 for exec audiences; tables count rows not words |
| Table rows | ≤ 7; more → appendix with a summary row on the body slide |
| Chart | One per slide; title is the finding; axis labels; source line |
| Appendix | Unlimited; referenced from body slides ("detail: A3") |

Overflow handling: move to appendix → merge duplicates → cut non-decision content. Never shrink fonts below the template minimum.

## 5. Numbers discipline
| Case | Action |
|---|---|
| Number with a source in provided materials | Keep; add source line on the slide or in notes |
| Number with no source | `[TO BE BASELINED — owner: ___]` in place of the number; note which source would confirm |
| Number that conflicts between slides | Flag both; `[TBD]` until reconciled; name the owner |
| Role or name not in materials | `[TBD — owner]`; never invent an owner |
| Date not in materials | `[TBD — owner]`; never pick a plausible date |
| Percentage without a base | Add the base or `[TBD]` |

The redline never "improves" a number. It either sources it or marks it.

## 6. Speaker notes
| Rule | Practice |
|---|---|
| Length | ≤ 60 words |
| Content | The spoken point in one sentence · the one number to say aloud · the transition to the next slide |
| Alignment | Nothing in the notes that is not on the slide or in the sources |
| Anticipation | Optional one line: "If asked about X, answer: …" (only with sourced answer) |

## 7. Redline output discipline
- Verdict for every slide, including title and appendix slides.
- `[SHARPEN]` always includes the full rewritten title and body; a reason alone is not a redline.
- Parked content lists where it went (appendix slide number or "dropped — reason").
- Before/after rubric scores are shown; the after score is the self-check evidence.
- Chat response stays under 50 words; the artifact carries the detail.
