# Rules — what `ui_lint.py` flags, why, and how to fix it

Static, source-only heuristics over React component files: every `.tsx`/`.jsx`, plus the `.js`/`.ts` files that contain JSX — a JavaScript Next.js repo keeps components in `.js` (tests, stories, `.d.ts`, `node_modules`, `.next`, `dist`, `build`, `coverage` skipped). A `.js`/`.ts` file counts as a component when it returns or arrows into a JSX tag or fragment (`return (<…`, `return <…`, `=> <…`, `return (<>`), or imports `react`/`react-dom`/`next/*` and contains a JSX tag; `route`, `middleware`, `instrumentation` and `*.config` files never count. Plain utilities (comparisons like `a < b`, HTML in template strings) are therefore not scanned and cannot trip UI1–UI11. UI9 needs a TypeScript `Props` type, so it does not fire in plain JavaScript. Fixtures: `repo-violations`/`repo-clean` (TypeScript), `repo-js` (JavaScript brownfield shape: `.js` components, `route.js`, `middleware.js`, an AWS workflow). Every rule has a clean fixture that does not trigger it and a violation fixture that does (`evals/fixtures/`). Spread props (`{...rest}`) make a tag unknowable, so UI1–UI4 skip spread tags on purpose.

| Rule | Severity | Flags | Rationale | Fix |
|---|---|---|---|---|
| UI1 img-without-alt | high | `<img>` / `<Image>` with no `alt` attribute | Screen readers announce the file name or nothing (WCAG 1.1.1) | Add `alt="…"` that says what the image means; `alt=""` for decorative images |
| UI2 icon-button-without-name | high | `<button>` whose children are only elements (icon/svg) and no `aria-label`, `aria-labelledby` or `title` | The button is announced as "button" with no purpose (WCAG 4.1.2) | `aria-label="Delete order 1042"`, or add `<span className="sr-only">Delete</span>`; wrap in a shared `IconButton` that requires `label` |
| UI3 clickable-div | high | `<div>`/`<span>` with `onClick` missing any of `role`, `tabIndex`, `onKeyDown/Up/Press` | Not focusable, not announced, not keyboard-operable (WCAG 2.1.1, 4.1.2) | Use `<button type="button">` (or `<Link>`); if a div is unavoidable, add all three |
| UI4 input-without-label | high | `<input>`/`<select>`/`<textarea>` with no `<label htmlFor={id}>` in the file, no `aria-label`/`aria-labelledby`, not wrapped in `<label>` (hidden/submit/button/reset skipped) | Placeholder text is not a label (WCAG 1.3.1, 3.3.2) | `<label htmlFor="email">Email</label><input id="email" …/>` or wrap the control in the label |
| UI5 no-loading-state | medium | file uses `useQuery`/`useInfiniteQuery`/`useSWR`, or `useEffect` + `fetch`/axios, or declares an `isLoading`/`loading: boolean` prop, and renders no loading branch (`isLoading ?`/`&&`/`if (…)`, `<Skeleton>`, `<Spinner>`, `<Suspense>`, `aria-busy`, `fallback=`, `status === "pending"`) | Users see a blank or a flash of empty content; async state must be visible (WCAG 4.1.3 for announced status) | Render a skeleton/spinner with `role="status"` and `aria-busy`, or wrap in `<Suspense fallback>` |
| UI6 no-empty-state | medium | `{list.map(…)}` in JSX with no `list.length`, `!list`, `list.some/every`, `isEmpty(list)` in the file; `CONSTANT_LISTS` and arrays declared as literals in the file are exempt | An empty array renders nothing and the user cannot tell "no data" from "broken" | `if (items.length === 0) return <EmptyState …/>` before the map |
| UI7 fixed-width-over-600px | medium | inline `width`/`minWidth` > 600 (no `maxWidth: 100%`/`width: 100%`), or `w-[Npx]`/`min-w-[Npx]` with N > 600 and no `w-full`/`max-w-full`/breakpoint variant in the same className | Forces horizontal scroll on phones (WCAG 1.4.10 Reflow) | `className="w-full lg:w-[960px]"` or `max-w-full`; prefer `max-w-*` tokens |
| UI8 dangerous-html | high | `dangerouslySetInnerHTML` | Renders unsanitised HTML (XSS) | Render JSX from data; if HTML is unavoidable, sanitise (DOMPurify) server-side and document why |
| UI9 prop-sprawl | low | `interface/type *Props` with > 8 members that does not `extends`/`&`/`Pick`/`Omit`/`ComponentProps` | A component with 9+ ad-hoc props is doing several jobs and cannot be reused | Split into composed components or build the props from a shared type |
| UI10 inline-style-in-map | low | `style={{…}}` inside a `.map(` callback | A new object per row per render defeats memoisation in hot lists | Hoist the style object or use a class; compute per-row values with CSS variables |
| UI11 color-only-state | low | a className ternary with both `text-green-*` and `text-red-*` whose children have no state text (ternary/`&&`), icon, `sr-only`, `aria-*` or `title` | Colour-blind users cannot read the state (WCAG 1.4.1) — kept conservative to avoid noise | Add the word (`Paid`/`Overdue`) or an icon with `aria-label` next to the value |

## Severity and the gate
`high` = ships a defect for assistive-technology users or a security hole; new high findings fail the run (exit 1). `medium` = missing state or layout breaks on phones; `low` = reusability/perf. With `--baseline findings.csv` (an earlier run), matching findings are `known` and do not gate; rows no longer found are `resolved`.

## Known limits (false negatives/positives)
- Source heuristics only: no render, no DOM, no type information. Labels associated through a design-system `<Field>` wrapper, or a `<label htmlFor>` in another file, are not seen (UI4): pass the label as a prop or add `aria-label`.
- UI5 looks at one file; a loading state handled by a parent `<Suspense>` boundary is not seen — add `aria-busy` or a comment-free `Suspense` in the file, or record the finding in the baseline.
- UI6 cannot see an empty state rendered by a parent; UI11 only sees Tailwind `text-red-*`/`text-green-*` ternaries.
- Contrast, focus, target size and live-region announcements need a browser run (`webapp-testing-runner`); see `a11y-checklist.md`.
