# Skills Factory × Port — WP0: tenant discovery

Spec: *Skills Factory × Port — Real Integration Spec* (2026-10-23), §4.0 and §10 WP0. This document is the WP0 deliverable: the factory-side inventory (verified from source and the live database, 2026-10-23) plus the tenant inventory, which is generated read-only by `studio/scripts/port-inventory.mts` into `docs/PORT-TENANT-INVENTORY.md`. No blueprint, action, scorecard or entity is created by WP0.

## 3. Tenant inventory

Generated by the owner (credentials never leave his machine) and committed as `docs/PORT-TENANT-INVENTORY.md`:

```bash
cd ~/giri-skills && git fetch origin && git checkout wp0-port-tenant-inventory && git pull
cd studio && npm ci
export PORT_CLIENT_ID='<Port → Settings → Credentials → Client ID>'
export PORT_CLIENT_SECRET='<Port → Settings → Credentials → Client Secret>'
# Default base is https://api.port.io (the EU org per PORT.md). US accounts only:
# export PORT_API_URL='https://api.us.port.io'
node --experimental-strip-types scripts/port-inventory.mts ../docs/PORT-TENANT-INVENTORY.md
unset PORT_CLIENT_ID PORT_CLIENT_SECRET PORT_API_URL
cd .. && git add docs/PORT-TENANT-INVENTORY.md && git commit -m "wp0: Port tenant inventory (generated, read-only)" && git push
```

The script is read-only (`GET` plus the token call and entity search), writes no secret or token to the file (covered by `studio/tests/port-inventory.test.ts`), and marks any route the account does not expose as "not available" rather than guessing.

Still to be filled in by hand in that file (not readable through the API): plan name and blueprint/action limits (Port → Settings → Billing), and the workflows list (Port → Workflows).
