# Quality Bar (applies to every skill in this repo)

Standard: Big 4 / Fortune 50 executive-facing quality. If a partner or a CIO would not sign it, it is not done.

## Non-negotiables
| Rule | What it means in practice |
|---|---|
| Bottom line up front | First line = the answer, decision, or deliverable. No preamble, no restating the ask. |
| Tables over prose | Anything with 3+ comparable items is a table. Prose only for narrative that cannot be tabulated. |
| No filler | No "In today's fast-paced world", no hedging paragraphs, no closing pleasantries. |
| No invented facts | Every number, date, name, rate, or role is either (a) from a provided source, (b) explicitly labeled an assumption, or (c) marked `TBD — owner: <name>`. Never fabricate a plausible figure. |
| Mark unknowns | Use `[TO BE BASELINED — owner: <role>]` for anything requiring client/stakeholder confirmation; always name the accountable role. |
| Copy-paste ready | Output is final-form: correct headings, consistent units, consistent tense, no "insert X here" unless it is a declared template placeholder. |
| Source every claim | External facts carry a source line (URL or document + page/slide). |
| One topic per deliverable | Do not bolt unrelated findings onto a deliverable; list them under "Out of scope / parked". |
| ≤50-word replies in chat | Chat responses stay under 50 words unless the task is the artifact itself. |

## Executive artifacts checklist
- [ ] Title states the decision or outcome, not the topic
- [ ] Exec summary ≤ 5 bullets, each a claim with a number or a consequence
- [ ] Every section answers "so what?" in its first line
- [ ] Risks have likelihood, impact, mitigation, owner
- [ ] Next steps have owner + date
- [ ] Appendix holds detail; body holds argument
- [ ] Numbers reconcile across sections (totals match)

## Redline convention (for reworking an existing artifact)
Stay close to the original storyline and sharpen it. Do not replace the narrative. For each unit (slide, section, paragraph):
```
[KEEP]    unchanged
[SHARPEN] rewrite — reason
[CUT]     reason
[ADD]     reason, source
[TBD]     needs baseline — owner
```
